# セッションと CSRF

リクエストをまたいで値を覚えておく仕組みです。このページで分かることは 3 つです。

- セッションの準備と使い方
- 別のサイトからの書き込みを防ぐ仕組み（CSRF）の使い方
- Cookie の扱い

## 準備

### 1. 鍵を作る

**`APP_KEY` が要ります。** Cookie の署名に使います。

```sh
cargo artisan key:generate
```

| こと       | 内容                                                    |
|------------|---------------------------------------------------------|
| 書き込み先 | `.env`                                                  |
| 長さ       | **64 文字以上が必須**。無い・短いとリクエストが 500 になる |
| 作り直すと | いまのセッションと署名付き URL が**全部無効**になる     |

くわしくは [configuration.md](configuration.md) にあります。

### 2. ミドルウェアを登録する

`bootstrap/app.rs` に 2 つ登録します。**順番が大事です。** 逆に置くと 500 になります。

```rust
Application::configure()
    .with_middleware(|m| {
        m.append(StartSession::from_env())      // 先に
            .append(VerifyCsrfToken::new())     // 後に
    })
    .with_routing(|r| r.web(crate::routes::web::routes))
    .create()
```

## セッションを使う

```rust
pub async fn store(req: Request) -> Result<Response> {
    req.session().put("cart", "12");
    req.session().flash("status", "保存しました");
    redirect().route("home")
}
```

| メソッド               | 中身                                   |
|------------------------|----------------------------------------|
| `get(key)`             | 読む。無ければ `None`                  |
| `get_or(key, default)` | 読む。無ければ既定値                   |
| `put(key, value)`      | 入れる。次のリクエストでも読める       |
| `flash(key, value)`    | 入れる。**次のリクエストまで**だけ残る |
| `has(key)`             | あるか                                 |
| `forget(key)`          | 消す                                   |
| `pull(key)`            | 読んでから消す                         |
| `all()`                | 全部の組（`__` で始まる鍵は入らない）  |
| `old(key)`             | 検査に落ちたときの入力（[validation.md](validation.md)） |
| `intended()`           | ログイン後の戻り先。**読むと消える**（[authentication.md](authentication.md)） |
| `id()`                 | いまのセッションの ID                  |
| `flush()`              | 中身を全部消す                         |
| `regenerate()`         | ID を作り直す。CSRF トークンも作り直す |
| `invalidate()`         | 中身を消して ID も作り直す             |

- 値は文字列です。
- 同じ鍵に `put` と `flash` の両方を書いたときは、**書いた順番に関係なく**
  `get` で `flash` のほうが読めます。
- `all()` だけは、前の回から持ち越した `flash` と今回の `put` が同じ鍵のとき、
  `put` の値を返します（[backlog.md](backlog.md)）。

### flash の寿命

```rust
// 1回目
req.session().flash("status", "保存しました");   // この回でも読める

// 2回目
req.session().get("status")   // Some("保存しました")

// 3回目
req.session().get("status")   // None
```

### `__` で始まる鍵は使わない

`__` で始まる鍵は、フレームワークが中で使います。

| 鍵             | 中身                   | 取り出し方         |
|----------------|------------------------|--------------------|
| `__csrf_token` | CSRF のトークン        | `req.csrf_token()` |
| `__old_input`  | 検査に落ちたときの入力 | `old(key)`         |
| `__flash:名前` | flash の持ち越しの目印 | `get(名前)`        |

- `put` / `flash` に `__` で始まる鍵を渡すと、**警告が出ます**（断りはしません）。
  思わぬ消え方をするので、別の名前にします。
- **`all()` には `__` で始まる鍵が入りません。** そのまま画面やログに出しても、
  トークンと入力し直し用の値は漏れません。

### ログインとログアウトは `req.auth()` で

```rust
req.auth().login(&user)?;    // セッション ID を作り直す
req.auth().logout()?;        // 中身を捨てて ID も作り直す
```

- **ログインの状態を自分で `put` しないでください。** `put("user_id", ..)` のように
  書いた値は、`auth` ミドルウェアにも `req.auth()` にも見えません。
- `login` が ID を作り直すのは、人のブラウザにあらかじめ ID を仕込んでおく攻撃
  （セッション固定）を防ぐためです。
- **ID を作り直すと、CSRF トークンも変わります。** ログイン前に受け取ったトークンは
  使えません。ログイン後にフォームを出すときは、トークンを取り直します。
- **ログアウトすると、セッションの Cookie も消えます**（`Max-Age=0` で返します）。
  同じリクエストで値を入れたとき（「ログアウトしました」の `flash` など）は、
  新しい ID で保存して、その Cookie を返します。

くわしくは [authentication.md](authentication.md) にあります。

## 置き場所

中身は **サーバー側**に置きます。ブラウザには ID だけを署名つきの Cookie で渡します。
中身がブラウザに出ないので、Cookie の 4 KB という上限にも縛られません。

| `SESSION_DRIVER`         | 置き場所                                   |
|--------------------------|--------------------------------------------|
| `file`（既定）           | `storage/framework/sessions/`              |
| `memory`（別名 `array`） | プロセスのメモリ。**テストと手元の確認用** |

- 知らない値（`redis` や書き間違い）は、**警告を出してから `file` にします。**
- `SESSION_LIFETIME` は分です（既定 120。1 より小さい値は 1 分にします）。
- **残りの期限が半分を切ったら、読むだけのリクエストでも期限を延ばします。**
- 期限切れのセッションは、書き込みのついでに少しずつ消します。
  まとめて消すなら `cargo artisan session:gc` です。
- **プロセスを 2 つ以上動かすときは、全プロセスが同じ `storage/` を見るようにします。**
  `memory` はプロセスをまたげないので、本番では使えません。
- 置き場所は平文のファイルです。秘密を入れすぎないでください。

`.env` を見ずに決めたいときは、次の作り方があります。

| 作り方                                   | 置き場所                             |
|------------------------------------------|--------------------------------------|
| `StartSession::from_env()`               | `.env` で決める                      |
| `StartSession::file()`                   | ファイル。期限は 120 分              |
| `StartSession::memory()`                 | メモリ。期限は 120 分                |
| `StartSession::new(置き場所, 設定)`      | 自分で作った置き場所（下の節）       |

### 同じセッションのリクエストは順番に処理する

**同じセッションのリクエストが同時に 2 本来ると、2 本目は 1 本目の応答が
終わるまで待ちます。** 待たせないと、片方が入れた値
（作ったばかりの CSRF トークンなど）が、もう片方の保存で消えるためです。

- **別のセッションどうしは待ちません。**
- 長くかかる処理は、**同じ利用者の次のリクエストを待たせます。**
- Laravel の既定とは違います。Laravel が順番にするのは、ルートに `block()` を付けたときだけです。
- **順番にするのは 1 つのプロセスの中だけです。** プロセスを 2 つ以上動かすと、
  別々のプロセスに入った同じセッションのリクエストは並んで走り、
  **後から保存したほうが勝ちます。**

### ルートに当たらないリクエストは読むだけ

静的ファイル・404・405 のように **ルートに当たらなかったリクエスト**でも、
`req.session()` と `req.auth()` は使えます。ただし扱いは「読むだけ」です。

| こと           | ルートに当たった     | ルートに当たらなかった |
|----------------|----------------------|------------------------|
| 順番に処理する | する                 | **しない**（待たない） |
| 期限を延ばす   | する                 | しない                 |
| flash          | 読めて、そこで消える | 読めるが、**消えない** |
| `Set-Cookie`   | 返す                 | 書き換えたときだけ返す |

- 画面 1 枚と CSS・画像が、1 本ずつにならずに並んで返ります。
- 転送先が 404 でも、`flash` は次の画面まで残ります。
- 共通のミドルウェアがセッションを書き換えたときは、**変えた鍵だけ**を保存します。
- 読んだあとでセッションが消えていたとき（同時にログアウトしたなど）は、
  その書き換えは保存しません。

## Cookie の設定

| 属性       | 既定                          | 意味                                 |
|------------|-------------------------------|--------------------------------------|
| 名前       | `bengara_session`             |                                      |
| `HttpOnly` | 付く（変えられない）          | JavaScript から読めない              |
| `SameSite` | `Lax`                         | 他のサイトからの書き込みでは送らない |
| `Secure`   | `APP_ENV=production` なら強制 | HTTPS のときだけ送る                 |
| `Path`     | `/`                           |                                      |

変えたいときは `SessionConfig` を渡します。

```rust
StartSession::from_env().with_config(SessionConfig {
    cookie: "myapp_session".into(),
    same_site: SameSite::Strict,
    lifetime_secs: 60 * 120,
    ..SessionConfig::default()
})
```

| 欄              | 既定              | 中身                           |
|-----------------|-------------------|--------------------------------|
| `cookie`        | `bengara_session` | Cookie の名前                  |
| `lifetime_secs` | 7200              | 放っておいて消えるまでの秒数   |
| `secure`        | `false`           | 本番では必ず `true` になる     |
| `same_site`     | `SameSite::Lax`   | 他のサイトから来たときの扱い   |
| `path`          | `/`               | Cookie を送る範囲              |

- **`with_config` は `.env` の `SESSION_LIFETIME` を上書きします。**
  `lifetime_secs` を省くと 7200 秒になります。合わせたいときは、同じ秒数を書きます。
- 期限を変えると、組み込みの置き場所を作り直します。
  `memory` のときは、それまでに入れた中身が消えます。

## CSRF

`GET` / `HEAD` / `OPTIONS` は素通しします。
それ以外のメソッドでトークンを確かめ、合わなければ **419** を返します。

### フォームから送る

トークンは `req.csrf_token()` で取り出します。`_token` という名前で送り返します。

```rust
let token = req.csrf_token();
html(format!(
    r#"<form method="post" action="/posts">
         <input type="hidden" name="_token" value="{token}">
       </form>"#
))
```

### SPA から送る

トークンを配るルートを 1 本作ります。以後は `X-CSRF-TOKEN` ヘッダーに入れて送ります。

```rust
// routes/web.rs
Route::get("/csrf-token", PostController::token).name("csrf.token");

// コントローラ
pub async fn token(req: Request) -> Result<Response> {
    json(&json!({ "token": req.csrf_token() }))
}
```

- トークンは **ヘッダーを先に**見ます。ヘッダーに無いときだけ `_token` を見ます。
- **ログインのあとは、このルートをもう一度呼んでトークンを取り直します。**

### ルートに当たらないときは確かめない

**ルートに当たらなかったリクエストでは、CSRF を確かめません。**
無いページへの POST は 419 ではなく 404 のままです。
トークンも用意しないので、Cookie を持たない人が無いページを叩いても、
`Set-Cookie` は返らず、セッションのファイルも増えません。

### 確かめない場所を決める

外し方は 2 つあります。**ルート名で外すほうを勧めます。**
パスで外すと、ルートを直したときに外しすぎ・外し漏れが静かに起きます。

| 書き方                  | 見るもの     | 備考                           |
|-------------------------|--------------|--------------------------------|
| `except_route(pattern)` | ルートの名前 | **こちらを勧めます**           |
| `except(pattern)`       | パス         | 名前の無いルートを外すときだけ |

```rust
VerifyCsrfToken::new()
    .except_route("webhook")      // 名前が webhook のルート
    .except_route("api.stripe.*") // api.stripe. で始まる名前のルート
    .except("/webhook")           // パスで外す
```

- どちらも末尾の `*` で前方一致になります。
- **`*` を付けた名前の頭に後から足したルートも、自動的に外れます。**
  ログイン中の人を見る処理を、外したグループに入れないでください。
- **名前の無いルートは `except_route` では外せません。**
- **パスの `*` の直前は `/` にします。** `.except("/admin*")` は `/administration` にも
  当たります。`.except("/admin/*")` と書きます。直前が `/` でないときは、
  起動時に警告が出ます（禁止はしていません）。

### 外してよいのは Cookie で認証しない処理だけ

**`/api/*` のようにまとめて外さないでください。**
`StartSession` は全ルートに掛かるので、`/api/*` も Cookie で認証されます。
そこで CSRF だけ外すと、**別のサイトから Cookie に便乗して書き込めます。**

| 外してよいもの                  | 相手の確かめ方           |
|---------------------------------|--------------------------|
| トークンや署名で認証する API    | そのトークン・署名       |
| 外から呼ばれる受け口（webhook） | 署名の検証など、別の方法 |
| ログイン中の人を見ない処理      | 確かめる相手がいない     |

## 自分で Cookie を扱う

```rust
let theme = req.cookie("theme").unwrap_or_else(|| "light".into());

let cookie = Cookie::new("theme", "dark")
    .with_max_age(3600)
    .with_same_site(SameSite::Strict);
Ok(response.with_cookie(&cookie))
```

| メソッド               | 既定        | 中身                                        |
|------------------------|-------------|---------------------------------------------|
| `with_path(path)`      | `/`         | 送る範囲のパス                              |
| `with_domain(domain)`  | 付けない    | 送る範囲のドメイン                          |
| `with_max_age(秒)`     | 付けない    | 生きている秒数。付けなければブラウザを閉じるまで |
| `with_secure(bool)`    | `false`     | HTTPS のときだけ送る                        |
| `with_http_only(bool)` | `true`      | JavaScript から読めなくする                 |
| `with_same_site(値)`   | `Lax`       | `Strict` / `Lax` / `None`                   |

- 消すときは `Cookie::removal("theme")` です。
- `SameSite::None` を選ぶと、`Secure` も自動で付きます。
- **名前と値は自動で符号化します。** `;` や空白を入れても壊れません。
- **`with_path` と `with_domain` の値からは、制御文字（改行など）と `;` を落とします。**
  落としたときは警告が 1 行出ます。

## `StartSession` を忘れたとき

| 呼んだもの                                          | 起きること                   |
|-----------------------------------------------------|------------------------------|
| `req.session()` / `req.csrf_token()`                | **パニック**（500）          |
| `VerifyCsrfToken`                                   | **500 のエラー**             |
| `req.auth()` の `login` / `attempt` / `logout` など | **500 のエラー**             |
| `req.auth()` の `check()` / `guest()` / `id()`      | 「ログインしていない」になる |

- エラーのメッセージには「`StartSession` を登録してください」が入ります。
- `check()` のように真偽値を返すものは、**黙って「ログインしていない」になります。**
  画面の出し分けだけに使っていると気づけません。
- セッションが無くてもよい場面では `req.try_session()` を使います。

## 自分で置き場所を作るとき

組み込みの `file` と `memory` で足りるなら、この節は読まなくて構いません。
別の置き場所（DB など）を使いたいときは、`SessionStore` を実装します。

```rust
StartSession::new(MyStore::new(7200), SessionConfig::default())
```

**期限の秒数は、置き場所にも自分で渡します。**
`with_config` で期限を変えても、自分で作った置き場所は作り直されません（警告が出ます）。

| メソッド                                 | 既定の実装                  |
|------------------------------------------|-----------------------------|
| `read` / `write` / `destroy`             | なし。必ず書く              |
| `touch(id)`                              | あり（`read` して `write`） |
| `read_and_touch(id)`                     | あり（`read` して `touch`） |
| `destroy_for_user(user_id)`              | あり（何もせず 0 を返す）   |
| `destroy_for_user_except(user_id, keep)` | あり（何もせず 0 を返す）   |
| `mark_revoked(user_id, except)`          | あり（何もしない）          |
| `revoked_at(user_id, session_id)`        | あり（`None`）              |

後ろの 6 つは、実装しなくても壊れません。必要になったときに足します。

| メソッド            | 守ること                                                           |
|---------------------|--------------------------------------------------------------------|
| `read`              | **期限切れには `None` を返す。** 返さないと、切れたセッションが生き返る |
| `touch`             | 期限だけを延ばす。**期限切れのセッションは延ばさない**             |
| `read_and_touch`    | ルートに当たったリクエストの最初に 1 回呼ばれる。読んで、期限も延ばす |
| `destroy_for_user` 系 | ある利用者のセッションを消す。消す前に `mark_revoked` を呼ぶ     |
| `mark_revoked`      | 「切った」印を付ける。**途中が読まれない形で書く**（別の名前に書いてから置き換える） |
| `revoked_at`        | 印の時刻を返す。**古い印は返さない**（組み込みは 1 時間）          |

- `touch` と `read_and_touch` は、既定のままだと読み書きが余分に走ります。
  安く書ける置き場所（DB なら `update` 1 文）では、自分で実装します。
- 「切った」印は、消した瞬間に処理中だった別のリクエストが、
  同じセッションを書き直して復活させないためのものです。
- `destroy_for_user` 系を実装していないと、`logout_other_devices()` などは
  警告を出して 0 を返します（[authentication.md](authentication.md)）。

### 組み込みの置き場所の掃除

| こと           | `file`                                            | `memory`                 |
|----------------|---------------------------------------------------|--------------------------|
| 掃除の起こり方 | 書き込みの約 2.3%（256 回に 6 回）                | 書き込みの 100 回に 1 回 |
| 1 回で見る数   | 最大 500 件。残りは次の機会                       | 全部                     |
| どこで走るか   | 別のスレッド。応答は待たない                      | その場                   |
| ファイルの権限 | ファイル `0600`、ディレクトリ `0700`（Unix だけ） | —                        |

- `file` は同じときに、書きかけのまま残った一時ファイル（5 分より古いもの）と、
  1 時間より古い「切った」印も消します。
- `cargo artisan session:gc` は、上限なしで全部を見ます。
