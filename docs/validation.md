# 入力の検査（バリデーション）

送られてきた値が決めた形になっているかを確かめます。Laravel の Validation に当たります。
このページで分かることは 3 つです。

- 入力の読み方と、検査の書き方
- 使える規則と、その数え方
- 検査に落ちたときに返るもの

## 入力を読む

| メソッド                           | 読むところ                   |
|------------------------------------|------------------------------|
| `req.input("title")`               | 本文とクエリ。**本文が優先** |
| `req.input_all()`                  | 同上。全部                   |
| `req.form("title")` / `form_all()` | フォームの本文だけ           |
| `req.query("q")` / `query_all()`   | クエリだけ                   |
| `req.json::<T>()`                  | 本文を型に読む               |

- 本文を読むのは、`Content-Type` がフォーム（`application/x-www-form-urlencoded`）か
  JSON のときです。
- JSON は**最上位の値だけ**を読みます。数値や真偽値は、見たままの文字になります。
  入れ子は `req.json::<T>()` で読みます。
- 同じ名前が何個も届いたときは、最初の 1 個を使います。

## 検査する

```rust
pub async fn store(req: Request) -> Result<Response> {
    let input = req.validate(&[
        ("title", "required|max:255"),
        ("email", "required|email"),
        ("age",   "nullable|integer|between:0,150"),
    ])?;

    let title = input.get("title");
    let age: i64 = input.get_as("age").unwrap_or(0);
    // ...
}
```

`?` で返すと **422** になります。自分で `match` する必要はありません。

## 通った値

検査を通った値は `Validated` に入ります。

| メソッド             | 中身                                   |
|----------------------|----------------------------------------|
| `get(field)`         | 値。無ければ空文字                     |
| `try_get(field)`     | 値。**検査した項目に無ければ** `None`  |
| `get_as::<T>(field)` | 型を変えて取り出す。変えられなければエラー |
| `all()`              | 全部の組                               |
| `has(field)`         | 検査した項目に入っているか             |

**入るのは検査した項目だけです。** 規則を書かなかった項目は入りません。

| 送ったもの       | 規則              | 入るもの       |
|------------------|-------------------|----------------|
| 何も送らない     | `max:10`          | **入らない**   |
| 何も送らない     | `nullable`        | 空文字         |
| `age=""`         | `nullable`        | 空文字         |
| `password="   "` | `nullable\|min:8` | **空文字**     |

**`try_get` と `has` では「送られてきたか」は分かりません。**
`nullable` の項目は、送られてこなくても `try_get` が `Some("")`、`has` が `true` です。

### 前後の空白は落とす

**値の前後の空白を落としてから検査します。** Laravel の `TrimStrings` と同じです。

- `age=" 5 "` は `5` として検査します。`Validated` に入る値も `5` です。
- 間の空白はそのままです。`"a b"` は `"a b"` のままです。
- `req.input()` で直に読むと、**送られてきたまま**です。

**次の 3 つだけは落としません。**

```
current_password  password  password_confirmation
```

そのため `password` の `min:8` は、前後の空白も 1 文字として数えます。

## 使える規則

規則は `|` でつなぎます。

| 分類       | 規則                                               |
|------------|----------------------------------------------------|
| 必須と省略 | `required`、`nullable`                             |
| 型         | `integer`（`int`）、`numeric`、`boolean`（`bool`） |
| 形         | `email`、`url`、`alpha`、`alpha_num`、`alpha_dash` |
| 大きさ     | `min:n`、`max:n`、`between:a,b`、`size:n`          |
| 値         | `in:a,b,c`、`starts_with:x`、`ends_with:x`         |
| 項目どうし | `confirmed`、`same:other`、`different:other`       |

一言添えておくものです。

| 規則         | 通るもの                                                         |
|--------------|------------------------------------------------------------------|
| `boolean`    | `1` `0` `true` `false` `on` `off` `yes` `no`                     |
| `numeric`    | 数として読める値。`inf` / `NaN` / `1e400` は通さない             |
| `email`      | `@` が 1 つあり、後ろに `.` がある。空白を含まない               |
| `url`        | `http://` か `https://` で始まる                                 |
| `alpha` など | 「文字」かどうかを見る。**ひらがな・漢字も通る**（Laravel と同じ）|
| `confirmed`  | `password` に付けると、`password_confirmation` と同じかを見る    |

英数字だけに限りたいときは、自分で確かめます。

### min / max / between / size の数え方

**`numeric` か `integer` が付いているときだけ、値の大小で比べます。**
付いていなければ**文字数**で比べます。Laravel と同じです。

| 書き方                        | 比べるもの           |
|-------------------------------|----------------------|
| `("age", "integer\|min:18")`  | 値（18 以上）        |
| `("age", "numeric\|max:9.5")` | 値（9.5 以下）       |
| `("title", "min:3")`          | 文字数（3 文字以上） |

間違えやすい例です。

| 書き方                            | 送った値        | 結果                       |
|-----------------------------------|-----------------|----------------------------|
| `("password", "required\|min:8")` | `password=9`    | **落ちる**（1 文字だから） |
| `("title", "max:50")`             | `title=9999999` | **通る**（7 文字だから）   |

- 数の大小で比べたいときは、`integer` か `numeric` を足します。
- 文字数はバイト数ではありません。`あいう` は 3 文字です。
- 数値として読めない値には、大きさの規則は何も言いません。
  `("n", "integer|min:5")` に `abc` を送ると、理由は「整数で入力してください」の 1 件だけです。

### 空文字も検査する

**検査を飛ばすのは、下の 2 つのときだけです。**

| 状況                             | 動き         |
|----------------------------------|--------------|
| 項目が送られてこなかった         | 検査しない   |
| 空で、`nullable` が付いている    | 検査しない   |
| **空文字（`""`）が送られてきた** | **検査する** |

`("role", "in:admin,user")` に `role=""` を送ると落ちます。
空でよい項目には `nullable` を付けます。

```rust
("role", "nullable|in:admin,user")
("name", "nullable|alpha")
```

`required` を付けた項目は、空文字でも空白だけでも「必ず入力してください」で落ちます。

## 落ちたとき

### JSON を求めた相手には JSON

```json
{
  "message": "入力に誤りがあります。",
  "errors": {
    "email": ["email はメールアドレスの形で入力してください。"],
    "title": ["title は必ず入力してください。"]
  }
}
```

- 1 つの項目に理由が複数付くことがあります。項目は名前の順に並びます。
- それ以外の相手には、同じ理由を並べた画面を返します。どちらで返すかの決め方は
  [requests-and-responses.md](requests-and-responses.md) にあります。
- **検査メッセージは日本語で固定です。** 多言語の仕組み（`resources/lang/`）とは
  つながっていません。言い回しを変えたいときは、下の「自分でエラーを組み立てる」を使います。

### 前の入力を覚えている

セッションを使っていれば、落ちた入力を次のリクエストで読めます。

```rust
req.session().old("title")   // 落ちたときに送られてきた title
```

覚えない場合が 3 つあります。

| 場合                                   | 理由                                         |
|----------------------------------------|----------------------------------------------|
| セッションの Cookie を持っていない相手 | 壊れた入力を送るだけでセッションを増やせないようにするため |
| 入力の合計が 64 KiB を超える           | 大きな入力をセッションに書かないため         |
| 秘密になりうる名前の項目               | 下の「覚えない項目」                         |

## 自分でエラーを組み立てる

DB を見る確認（重複など）は、自分で書いてここに足します。

```rust
let mut errors = ValidationErrors::default();
errors.add("title", "すでに同じ題名があります。");
if !errors.is_empty() {
    return Err(Error::Validation(Box::new(errors)));
}
```

| メソッド              | 中身                           |
|-----------------------|--------------------------------|
| `add(field, message)` | 理由を 1 件足す                |
| `is_empty()`          | 1 件も無いか                   |
| `has(field)`          | その項目に理由が付いているか   |
| `get(field)`          | その項目の理由                 |
| `first()`             | 最初の 1 件                    |
| `all()`               | 全部の組                       |
| `len()` / `total()`   | 項目の数 / 理由の総数          |

## 規則の書き間違いは 500 になる

**書き間違えた規則は、黙って通しません。500 になります。**
知らない規則名のときは、メッセージに使える規則名の一覧が出ます。

| 書き間違い                    | 理由                         |
|-------------------------------|------------------------------|
| `maxx:10`                     | 知らない規則名               |
| `min`                         | 引数を忘れた                 |
| `max:nan` `min:inf`           | 数として使えない             |
| `size:-3` `size:1.5`          | `size` は 0 以上の整数       |
| `between:10,1`                | 下限が上限より大きい         |
| `in:` `in:,,`                 | 許可値が 1 つも無い          |

`in:` の許可値からは、空のものを落とします。
`in:admin,user,` の末尾のカンマは無視するので、`role=`（空）は通りません。

## 覚えない項目

次の語を名前に含む項目は、`old()` では**覚えません**。
セッションのファイルに平文で残るのを避けるためです。
リクエストのログで `***` に伏せる項目も、同じ決まりです。

```
password  passwd  pwd  pass  passphrase  secret  token  key  apikey
credential  credentials  cvv  cvc  csc  card  ssn  otp  totp  pin
code  seed  mnemonic  recovery  backup  answer  signature
```

**語の単位で突き合わせます。** 大文字小文字は区別しません。

1. 名前を `_` `-` `.` `[` `]` 空白と、小文字から大文字へ変わる所で語に区切る。
2. 語の**末尾の数字を落として**から、上の一覧にあるかを見る。

| 名前                        | 覚えるか | 理由                            |
|-----------------------------|----------|---------------------------------|
| `new_password_confirmation` | 覚えない | `password` の語がある           |
| `password1` `password2`     | 覚えない | 末尾の数字を落とすと `password` |
| `apiKey` `apiKey2`          | 覚えない | 大文字の境目で `Key` に切れる   |
| `token[]`                   | 覚えない | `[` `]` で切って `token`        |
| `zip_code` `country_code`   | 覚えない | **`code` の語がある**           |
| `shipping_address`          | 覚える   | どの語も一覧に無い              |
| `keyword`                   | 覚える   | `key` を含むが語は `keyword`    |

**`zip_code` と `country_code` も覚えません。** 検査に落ちたフォームを出し直すと、
郵便番号の欄が空に戻ります。
