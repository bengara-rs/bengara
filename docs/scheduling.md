# 定期処理

決まった間隔で動かしたい処理を書く場所です。
このページで、処理の書き方・間隔の決め方・外からの呼び方が分かります。

**自動では動きません。** `schedule:run` を **1 分ごとに外から呼びます。**
呼ばれた回に、間隔が来ている処理だけが動きます。

```text
* * * * * cd /path/to/app && ./myapp schedule:run >> /dev/null 2>&1
```

Windows では、タスクスケジューラに 1 分おきの `myapp.exe schedule:run` を登録します。

## 書く

`routes/console.rs` に書きます。`init` が雛形を作ります。

```rust
//! routes/console.rs
use bengara::prelude::*;

pub fn schedule(s: &mut Schedule) {
    s.job("再設定トークンの掃除", Every::Hour, || async {
        PasswordReset::sweep_expired().await.map(|_| ())
    });

    s.job("記事数の集計", Every::Minutes(5), || async {
        let total = crate::app::models::Post::count().await?;
        Cache::put("stats.posts", total.to_string(), 600).await
    });
}
```

`job` に渡すのは、名前・間隔・処理の 3 つです。処理は `Result<()>` を返します。

アプリの中身は全部使えます。DB もキューも、画面のコードと同じように呼べます。

```rust
s.job("お知らせを積む", Every::Hour, || async {
    Queue::push_raw("SendReport", "{}").await?;
    Ok(())
});
```

### 間隔

| `Every`      | 間隔                                       |
|--------------|--------------------------------------------|
| `Minute`     | 呼ばれるたびに動かす（1 分ごとに呼ぶ前提） |
| `Minutes(n)` | n 分ごと                                   |
| `Hour`       | 1 時間ごと                                 |
| `Day`        | 1 日ごと                                   |
| `Seconds(n)` | n 秒ごと                                   |

- **「毎週月曜の 3 時」のような指定はできません。** 決められるのは間隔だけです。
- 間隔が 1 分以上の処理は、**30 秒早くても動きます。** cron が呼ぶ秒のぶれで 1 回飛ぶのを防ぐためです。
  `Seconds(n)` には、このゆとりがありません。

### 名前

名前は「前回いつ動いたか」を覚える鍵です。

| すること                 | どうなるか                   |
|--------------------------|------------------------------|
| 同じ名前を 2 回登録する  | 起動時にパニックする         |
| 名前を変える             | 別の処理として数え直す       |

## 動かす

```sh
cargo artisan schedule:run
```

```
  再設定トークンの掃除 成功（9 ms）
  記事数の集計 成功（2 ms）
2 件動かしました。
```

動かすものが無い回は `いま動かすものはありません。` と出ます。

登録の一覧は `schedule:list` で見られます。まだ動いていない処理の「前回」は `まだ` です。

```
名前                  間隔        前回
再設定トークンの掃除  1 時間ごと  2026-10-05 10:17:00
記事数の集計          5 分ごと    2026-10-05 10:17:00

2 件
```

### 失敗したとき

**1 つ失敗しても、残りの処理は動きます。**

| 起きたこと                           | 出る文                                 |
|--------------------------------------|----------------------------------------|
| `Err` を返した                       | `名前 失敗: 理由`                      |
| パニックした                         | `名前 失敗: 処理がパニックしました`    |
| 前回の時刻か錠ファイルを書けなかった | `名前 失敗（動かせませんでした）: 理由` |

- **失敗した処理は、次の間隔まで動きません。** 時刻は動かす前に書くためです。
- 3 つめは、処理を動かしていません。`storage/framework/schedule/` の権限と空き容量を確かめてください。
  直るまで、毎回この失敗になります。

### 終了コード

| 終了コード | いつ                                                              |
|------------|-------------------------------------------------------------------|
| `0`        | 失敗が 1 件も無い（動かすものが無かった回・錠で飛ばした回を含む） |
| `1`        | 上の表の失敗が **1 件でも**あった。`storage/` が無いときも `1`    |

失敗があると、残りを全部動かしたあと、最後に次の文が出ます。

```
エラー: 定期処理が 1 件失敗しました（記事数の集計）
```

cron の側で拾う例です。

```text
* * * * * cd /path/to/app && ./myapp schedule:run >> /dev/null 2>&1 || logger -t myapp "schedule:run が失敗しました"
```

## 同時に呼ばれたとき

2 つの `schedule:run` が同時に来ても、間隔のある処理（`Every::Minute` 以外）を
**その回に動かすのは片方だけです。** 2 台が同じ `storage/` を共有しているときも同じです。

「動かすかどうか」を決める間だけ、処理ごとに錠ファイルを取ります。
錠が取れなかった側は、次の文を出してその処理を飛ばします。失敗には数えません。

```
  名前 は飛ばします（錠を取れませんでした。別の schedule:run が判定中です）
```

**処理の重なりは防ぎません。** 次の 2 つは並んで動きます。

| 場合                                   | 起きること                                 |
|----------------------------------------|--------------------------------------------|
| 処理が間隔より長くかかる               | 終わる前に、次の回の分が始まる             |
| `Every::Minute` を 2 か所から同時に呼ぶ | 両方で動く（毎回動かす指定のため）         |

**長くかかる処理は [キュー](queue.md) に積んでください。**
`schedule:run` は 1 か所の cron からだけ呼びます。

## 前回の時刻の置き場所

最後に動かした時刻は、**`storage/framework/schedule/` のファイル**に置きます。
処理 1 つにつきファイル 1 つです。

| 知っておくこと     | 内容                                                               |
|--------------------|--------------------------------------------------------------------|
| キャッシュとの関係 | ありません。`CACHE_DRIVER` が何でも間隔は効き、`cache:clear` でも消えません |
| やり直したいとき   | `storage/framework/schedule/` の中を消す                           |
| ディレクトリ       | 無ければ `schedule:run` が作る（`storage:init` も作る）。権限は所有者だけ（Unix で 0700） |
| `storage/` が無い  | 作らずに、エラーを出して終わる                                     |
| 覚える時刻         | 間隔が 1 分以上の処理は、分の頭に丸める                            |
| 時計が戻ったとき   | 前回がいまより後なら、警告を出して動かす                           |

## できないこと

| できないこと                              | 代わりにすること                    |
|-------------------------------------------|-------------------------------------|
| cron の式（`0 3 * * 1`）や時刻の指定      | `Every` で間隔を決める              |
| 常駐して自分で動く（`schedule:work`）     | cron から `schedule:run` を呼ぶ     |
| 処理の重なりを防ぐ（`withoutOverlapping`） | 長い処理はキューに積む             |

まだ無い機能の一覧は [backlog.md](backlog.md) にあります。
