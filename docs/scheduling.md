# 定期処理

決まった間隔で動かしたい処理を書く場所です。

**自動では動きません。** `schedule:run` を **1 分ごとに外から呼びます。**
呼ばれた回に、間隔が来ている処理だけが動きます。

```text
* * * * * cd /path/to/app && ./myapp schedule:run >> /dev/null 2>&1
```

Windows では、タスクスケジューラに 1 分おきの `myapp.exe schedule:run` を登録します。

## 書く

`routes/console.rs` に書きます。`init` が雛形を作ります。

```rust
//! routes/console.rs
use bengara::prelude::*;

pub fn schedule(s: &mut Schedule) {
    s.job("再設定トークンの掃除", Every::Hour, || async {
        PasswordReset::sweep_expired().await.map(|_| ())
    });

    s.job("記事数の集計", Every::Minutes(5), || async {
        let total = crate::app::models::Post::count().await?;
        Cache::put("stats.posts", total.to_string(), 600).await
    });
}
```

- `job` に渡すのは、名前・間隔・処理の 3 つです。処理は `Result<()>` を返します。
- 中では DB もキューも、画面のコードと同じように使えます。

### 間隔

| `Every`      | 間隔                                       |
|--------------|--------------------------------------------|
| `Minute`     | 呼ばれるたびに動かす                       |
| `Minutes(n)` | n 分ごと                                   |
| `Hour`       | 1 時間ごと                                 |
| `Day`        | 1 日ごと                                   |
| `Seconds(n)` | n 秒ごと                                   |

- 決められるのは間隔だけです。「毎週月曜の 3 時」のような指定はできません。
- 間隔が 1 分以上の処理は、30 秒早くても動きます。cron の呼ぶ秒がぶれて 1 回飛ぶのを防ぐためです。
- `schedule:run` を呼ぶ間隔より細かくは動きません。60 秒未満の `Seconds(n)` は、登録時に警告が出ます。
- `Minutes(0)` と `Seconds(0)` は、起動時にパニックします。毎回動かすなら `Minute` です。

### 名前

名前は「前回いつ動いたか」を覚える鍵です。

- 同じ名前を 2 回登録すると、起動時にパニックします。
- 名前を変えると、別の処理として数え直します。

## 動かす

```sh
cargo artisan schedule:run
```

```
  再設定トークンの掃除 成功（9 ms）
  記事数の集計 成功（2 ms）
2 件動かしました。
```

動かすものが無い回は `いま動かすものはありません。` と出ます。

登録の一覧は `schedule:list` で見ます。まだ動いていない処理の「前回」は `まだ` です。

```
名前                  間隔        前回
再設定トークンの掃除  1 時間ごと  2026-10-05 10:17:00
記事数の集計          5 分ごと    2026-10-05 10:17:00

2 件
```

### 失敗したとき

**1 つ失敗しても、残りの処理は動きます。**

| 起きたこと                             | 出る文                                  |
|----------------------------------------|-----------------------------------------|
| `Err` を返した                         | `名前 失敗: 理由`                       |
| パニックした                           | `名前 失敗: 処理がパニックしました`     |
| 前回の時刻か錠ファイルを書けなかった   | `名前 失敗（動かせませんでした）: 理由` |

- 失敗した処理は、次の間隔まで動きません。時刻は動かす前に書くためです。
- 3 つめは、処理を動かしていません。`storage/framework/schedule/` の権限と空き容量を確かめてください。
- 失敗が 1 件でもあると、終了コードは `1` です。`storage/` が無いときも `1` です。

```
エラー: 定期処理が 1 件失敗しました（記事数の集計）
```

cron の側で拾う例です。

```text
* * * * * cd /path/to/app && ./myapp schedule:run >> /dev/null 2>&1 || logger -t myapp "schedule:run が失敗しました"
```

## 同時に呼ばれたとき

2 つの `schedule:run` が同時に来ても、その回に処理を動かすのは片方だけです（`Every::Minute` を除く）。
2 台で同じ `storage/` を共有しているときも同じです。

取れなかった側は、次の文を出してその処理を飛ばします。失敗には数えません。

```
  名前 は飛ばします（錠を取れませんでした。別の schedule:run が判定中です）
```

**処理の重なりは防ぎません。**

- 処理が間隔より長くかかると、終わる前に次の回の分が始まります。
- `Every::Minute` は、同時に呼ばれれば両方で動きます。

長くかかる処理は [キュー](queue.md) に積んでください。`schedule:run` は 1 か所の cron からだけ呼びます。

## 前回の時刻の置き場所

最後に動いた時刻は、`storage/framework/schedule/` のファイルに置きます（処理 1 つにファイル 1 つ）。

- キャッシュとは関係ありません。`cache:clear` でも消えません。
- やり直したいときは、このディレクトリの中を消します。
- ディレクトリが無ければ `schedule:run` が作ります。`storage/` そのものが無ければエラーです。
- 時計が戻って前回がいまより後になったときは、警告を出して動かします。

常駐して自分で動く形（Laravel の `schedule:work`）はありません。まだ無い機能は [backlog.md](backlog.md) にまとめています。
