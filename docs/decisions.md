## 1. 入口を `src/` から直下へ

- **決めたこと** — 入口はプロジェクト直下の `main.rs` と `artisan.rs`。`Cargo.toml` で `[[bin]] path` を指定し、
  `autobins = false` にする。
- **理由** — `src/` は Rust 固有の見た目で、Laravel の構成から浮く。Cargo の標準機能だけで消せる。
- **採らなかった案** — `src/main.rs` + `src/bin/artisan.rs`。Rust としては自然だが、Laravel の構成と並べたときに違和感が出る。
  `public/` は静的配信の対象なので入口を置けない。`bootstrap/` は自動検出の走査対象なので、入口を置くと衝突する。

## 2. `make:*` は作らない

- **決めたこと** — コードを生成するコマンド（`make:controller` など）を用意しない。
- **理由** — コントローラやモデルの雛形のような基本的なコードは、AI で生成できる。
- **採らなかった案** — Laravel と同じ一式を揃える。保守の手間に対して得られるものが小さい。

## 3. edition 2021 / MSRV 1.85 / resolver 2

- **決めたこと** — edition は 2021、最低対応 Rust（MSRV）は 1.85、resolver は 2。
- **理由** — ある程度古い安定版でもビルドできるようにする。
  bengara 自身のコードは edition 2021（1.82 相当）で書いているが、依存クレートの hyper-util が
  edition 2024 を要求するため、実際の下限は 1.85 になる（1.82 では依存の解決に失敗することを実測）。
- **採らなかった案** — edition 2024 と新しい MSRV。書きやすさは上がるが、使える環境が狭くなる。

## 4. `with_routing` は所有型のビルダー

- **決めたこと** — `with_routing` のクロージャは `FnOnce(Routing) -> Routing`。`Routing` を受け取って `Routing` を返す。
- **理由** — `&mut` を返すクロージャは Rust の型推論と相性が悪く、利用者側でエラーが読みにくくなる。
- **採らなかった案** — `FnOnce(&mut Routing)`。PHP では自然だが、Rust では書き味が悪くなる。

## 5. `config/` の自動登録はコード生成で行う

- **決めたこと** — `bengara-build` が、`config/` 直下の各ファイルの `pub fn config()` を呼ぶコードを生成する。
- **理由** — 実行時のリフレクションを使わずに済む。起動時にすべて確定する。
- **採らなかった案** — 実行時に探して登録する仕組み。Rust にはリフレクションが無く、別の仕掛けが必要になる。
- **代わりの約束** — `config/` 直下のファイルには `pub fn config() -> 何らかの型` を必ず書く。

## 6. 名前付きルートの URL は `route()` / `route_with()`

- **決めたこと** — `route(name)` と `route_with(name, &[(k, v)])` の 2 つ。どちらも `Result<String>` を返す。
- **理由** — Rust に可変長引数が無い。引数の有無で関数を分け、引数はスライスで渡す。
- **採らなかった案** — マクロで可変長にする。書き味は Laravel に近づくが、エラーが読みにくくなる。

## 7. `serve` の監視は更新時刻の見張り

- **決めたこと** — ファイルの更新時刻を 0.4 秒ごとに確認する。変更が続いている間は 0.25 秒待ってまとめて 1 回ビルドする。
- **理由** — OS ごとの通知の仕組み（`notify` クレート）を入れずに済み、依存クレートが増えない。
- **採らなかった案** — `notify` クレートを使う。反応は速いが、依存が増え、OS ごとの差に付き合うことになる。

## 8. ハンドラのパニックは `tokio::spawn` で捕まえる

- **決めたこと** — 各リクエストの処理を `tokio::spawn` に入れ、パニックを 1 リクエストに閉じ込めて 500 を返す。
- **理由** — `catch_unwind` のための追加クレートを入れずに済む。プロセスを落とさない。
- **採らなかった案** — `panic = "abort"` にする。パニックでプロセスが落ちるので、Web アプリには向かない。

## 9. テストの道具は `#[bengara::test]` が注入する

- **決めたこと** — `#[bengara::test]` を付けた関数の中で `client` `get` `post` がそのまま使える。
- **理由** — `use bengara::testing::*;` を毎回書かせたくない。Laravel のテストに近い書き味にする。
- **採らなかった案** — `use` を書かせる普通の形。素直だが、毎回の 1 行が増える。

## 10. 依存クレートは少なく保ち、重い部分はフラグにする

- **決めたこと** — 外部クレートは必要最小限にする。入れるものは広く使われていて信用できるものだけにする。
  `RUST_LOG` の細かい絞り込みは機能フラグ `log-filter`（既定で入っている）にした。
- **理由** — ビルド時間と更新の手間を抑えたい。一方で HTTP の下回りのように自作すると危ない部分は、
  実績のあるクレートに任せたい。`log-filter` を外すと依存が 3 つ減る。
- **採らなかった案** — 絞り込みを常に有効にする（外せない）／最初から外す（`RUST_LOG=myapp=debug` が
  書けなくなり、Rust 利用者の期待から外れる）。
  自前で書けるもの（`.env` の読み込み、Content-Type の判定、`Cargo.toml` の書き換え、引数の解釈）は、
  クレートを入れずに実装した。

## 11. ミドルウェアは関数で書く

- **決めたこと** — `async fn handle(req: Request, next: Next) -> Result<Response>` を既定の形にする。
  `Middleware` トレイトはこの形に自動で実装されるので、普通は手で書かない。
- **理由** — コントローラも関数なので形がそろう。トレイトの `async fn` は `dyn` にできず、
  手で書かせると `Box::pin(async move { ... })` を利用者に強いることになる。
- **採らなかった案** — トレイトの実装を必須にする。`tower` の `Service` を使う（依存と型が漏れる）。

## 12. `next.run()` は必ず成功を返す

- **決めたこと** — `next.run(req).await` が返すのはいつも `Ok`。内側のエラーはその場でレスポンスに変える。
- **理由** — そうしないと、レスポンスに手を入れるミドルウェアがエラーのときだけ素通りされる。
  403 や 500 にも共通のヘッダーを付けたい、という要求のほうが普通。
- **引き換えに失うもの** — 内側で起きた `Error` の中身はミドルウェアから見えない。

## 13. ルートのグループは登録のときに畳む

- **決めたこと** — `Route::prefix(...).group(...)` は、中のルートを登録する瞬間にパス・名前・
  ミドルウェアを畳む。親子の関係は持たない。ルート名の点は利用者が自分で書く。
- **理由** — 実行時の動きがグループの有無で変わらない。`route:list` に畳んだ結果が出るので、
  何が登録されたか一目で分かる。
- **採らなかった案** — 親子の木を保持して実行時にたどる。点を自動で足す（`admin..index` を防げない）。

## 14. テンプレート（ビュー）は当面作らない

- **決めたこと** — テンプレートエンジンを入れない。画面は `html(...)` に文字列を渡すか、
  JSON を返して別で作る。
- **理由** — Blade は PHP の実行が前提で作れない。代わりに Rust のエンジンを選ぶのは、
  「Laravel に似せる」話とは別の話で、利用者が自分で選べる領域でもある。
  テンプレートが無くても、バリデーション・セッション・CSRF は作れた。
- **やめたわけではない** — 必要になったら足します。足すときは `resources/views/` を自動検出し、
  リリースビルドではバイナリに埋め込む形にします。

## 15. 署名は自前の HMAC-SHA256、乱数は OS から

- **決めたこと** — SHA-256 と HMAC-SHA256 は自前で書き、公式のテストベクタ
  （FIPS 180-4 / RFC 4231）で確かめる。乱数は `getrandom` で OS からもらう。 **暗号化（中身を隠す処理）は作らない。**
  署名の照合は定数時間で行う。
- **理由** — 仕様が公開されていてテストで確かめられるものは自前で持ち、依存を少なく保つ。
  乱数だけは標準ライブラリに無く、推測できる値を使うと仕組みが成り立たないので借りる。
- **採らなかった案** — `sha2` + `hmac` クレート（依存が 7〜8 個増える）。乱数を自前で作る（やってはいけない）。

## 16. セッションは中身をサーバーに置き、ID だけを渡す

- **決めたこと** — 中身は置き場所（既定はファイル）に置き、ブラウザには署名つきの ID だけを渡す。
  置き場所は `SessionStore` トレイトで差し替えられる。
- **理由** — 中身を Cookie に入れると、署名はできても中身は読めてしまう。暗号化は自前で書かない
  方針なので、そもそも中身を出さない形にした。4 KB の上限にも縛られない。
- **実装で気をつけたこと** — 持ち越しの値（flash）を抱えているときは、読むだけでも保存する。
  しないと 1 回だけのはずの値が消えない。ID はファイル名になるので英数字とハイフン以外は断る。
  `Debug` に ID も中身も出さない。

## 17. エラーの見せ方は `Accept` で決め、差し替えもできる

- **決めたこと** — HTML で返すか JSON で返すかはリクエストを見て決める。
  `with_exceptions` で利用者が差し替えられる。
- **理由** — テンプレートを作らないので API として使われる前提が強い。
  一方、ブラウザで直接開いたときは読める画面のほうがよい。

## 18. 回数の制限はプロセスごとに数える

- **決めたこと** — `Throttle` は回数をプロセスのメモリに置く。超えたら 429 と `Retry-After`。
- **理由** — 共通の置き場所（Redis など）はまだ無い。無いものを待つより動くものを先に出す。
- **引き換えに失うもの** — **プロセスを 2 つ動かすと上限は約 2 倍になる。**
  厳密に守りたいときは前段のプロキシで掛けてください。

## 19. データベースは sqlx。SQLite から作り、機能フラグにする

- **決めたこと** — 下回りは sqlx。sqlx の型は外に出さない。 **まず SQLite だけ**を作り、
  機能フラグ `sqlite` で出し入れする。既定では入らない。
- **理由** — Laravel の既定も SQLite。ファイル1つで動き、用意するものが無い。
  3 つ同時に作るとどれも中途半端になるので、1 つで形を決めてから広げる。
  フラグにしたのは、DB を使わないアプリに依存を入れないため（依存の木が 59 → 133 に増える）。
- **引き換えに失うもの** — MySQL と PostgreSQL は **まだつながりません**（SQL の組み立てだけあります）。
  SQLite に列の変更が無いので、マイグレーションは「表を作る」「列を足す」「索引を足す」までです。
- **採らなかった案** — tokio-postgres（PostgreSQL 限定）、rusqlite（同期）、diesel や sea-orm
  （マクロと生成物が大きく、Laravel の書き味を上に載せにくい）。

## 20. `where` は `where_`、引数の数で名前を分ける

- **決めたこと** — Rust の予約語とぶつかる名前は末尾に `_` を付ける（`where_`）。
  Laravel が引数の数で使い分けるものは別の名前にする（`where_` と `where_op`）。
  Laravel が暗黙に見るものは引数で渡す（`paginate(15, req.page())`）。
- **理由** — `r#where` は書くたびに `r#` が付いて読みにくい。`filter` は Laravel の名前から離れる。
  Rust には引数の数による使い分け（オーバーロード）が無い。
  ページ番号を暗黙に読むと、クエリビルダがリクエストを知ることになる。
- **採らなかった案** — `r#where`、`filter`、タプルを渡す形（`where_(("age", ">", 18))`）。

## 21. 日時は文字列。chrono を入れない

- **決めたこと** — 日時専用の型を作らない。`created_at` などは `String` で、
  `YYYY-MM-DD HH:MM:SS`（UTC）。いまの時刻は `now()`。
- **理由** — chrono や time を入れると、 **その型があなたのコードに出ます。**
  下回りを隠す方針と合いません。比較と並べ替えは、この形の文字列なら辞書順で正しく動きます。
- **引き換えに失うもの** — 「3日後」のような計算はできません。必要なら chrono を自分で入れてください。
  タイムゾーンは UTC だけです。

## 22. リレーションはメソッド。触っただけでは読まない

- **決めたこと** — `hasMany` のような宣言は作らない。`impl` にメソッドを書く。
  `post.comments().get().await?` のように、読むときは `await` が付く。
- **理由** — **問い合わせが走る場所が目に見えます。** N+1 を起こしにくくなります。
  絞り込みも足せます（`post.comments().where_("spam", false)`）。
- **引き換えに失うもの** — 一覧に対するまとめ読み（Laravel の `with()`）は、
  `where_in` で引いて自分で束ねます。`group_by` ヘルパーを用意しました。

## 23. 表の名前は書く。推測しない

- **決めたこと** — `#[derive(Model)]` には `#[model(table = "posts")]` が必須。
- **理由** — 英語の複数形は規則が一定でない（`person` → `people`）。
  推測すると、当たらない場合の指定が必ず必要になる。1行書くほうが短い。

## 24. ファクトリは、ただの関数

- **決めたこと** — `Post::factory()->count(3)->create()` に当たる仕組みは作らない。
  `database/factories/` に関数を置く。
- **理由** — Rust では構造体をそのまま書けるので、属性を上書きする仕組みが要らない。
  件数の指定は `for` で書ける。

## 25. DB を使うテストは札で順番を守る

- **決めたこと** — `let _db = refresh_database().await;` が返す札を持っている間だけ DB を使える。
  テスト用の DB は `DB_TEST_DATABASE`（既定 `:memory:`）で、開発用とは分ける。
- **理由** — `cargo test` はテストを並列に走らせる。1 つの DB を共有すると件数の確認が狂う。
  札（ガード）にすると、受け取るだけでよく、後始末を書かなくてよい。
- **引き換えに失うもの** — **DB を使うテストは順番に走ります。**
  `:memory:` なら1本あたり数ミリ秒です。

## 26. `unique` / `exists` のバリデーション規則は作らない

- **決めたこと** — 入力の検査に `unique:posts,title` のような規則を足さない。
  重なりの確認はクエリで書く（`DB::table("posts").where_(...).exists().await?`）。
- **理由** — `req.validate(...)` は同期の関数。中で DB を待つには非同期にするしかなく、
  すべての呼び出し側が変わる。規則の文字列に表と列の名前を埋め込むと、
  打ち間違いがコンパイルで見つからない。

## 27. パスワードは PBKDF2-HMAC-SHA256。依存は増やさない

- **決めたこと** — パスワードの変換は PBKDF2-HMAC-SHA256（RFC 8018）を自前で実装する。
  既にある HMAC-SHA256 で書けるので **依存クレートは増えません。**
  回数は既定 120,000（リリースビルドで実測 0.23 秒）。保存する形に方式と回数を埋める。
- **理由** — Argon2 と bcrypt はどちらも依存が増える。まず依存ゼロで動くものを置く。
  回数を形に埋めたので、 **後から回数を上げても古いパスワードが照合できます。**
- **引き換えに失うもの** — **PBKDF2 はメモリハードではありません。**
  専用の機械（GPU）で総当たりされると Argon2 より早く破られます。回数で補いますが限界があります。
  必要になったら Argon2 を機能フラグで足します（[backlog.md](backlog.md)）。
  デバッグビルドでは 1 回 3.6 秒かかるため、テストでは自動で 1,000 回に下げます。

## 28. ログイン中の人は `req.auth()` から取る

- **決めたこと** — `Auth::user()` のように、どこからでも読める形は作らない。
  `req.auth().user::<User>().await?` のように、リクエストから取る。
- **理由** — ハンドラは内部で別のタスクとして動くため、タスクに紐づけた値が引き継がれません
  （パニックを 1 リクエストに閉じ込める作りのためです）。
  また、返す型（アプリの `User`）をフレームワークが知りません。
- **引き換えに失うもの** — `req` を持ち回る必要があります。
  `user()` は **呼ぶたびに DB を引きます**（何度も使うなら変数に入れてください）。

## 29. 認可は「ただの関数」と `authorize(bool)`

- **決めたこと** — `Gate::define` のような登録表は作らない。
  判定は `app/Policies/` に `pub fn update(user: &User, post: &Post) -> bool` として書き、
  `authorize(PostPolicy::update(&user, &post))?` で止める。
- **理由** — 文字列で引く表は、打ち間違いがコンパイルで見つかりません。
  関数なら名前を間違えればビルドが止まり、単体テストもそのまま書けます。
- **引き換えに失うもの** — Laravel と書き方が変わります。呼ぶ側が関数を指定します。

## 30. 暗号化はクレートに任せる。機能フラグにする

- **決めたこと** — `encrypt` / `decrypt` の中身は `chacha20poly1305`（RFC 8439）。
  機能フラグ `encryption` で出し入れし、既定では入れない。鍵は `APP_KEY`。
- **理由** — 署名（SHA-256 / HMAC）は自前ですが、暗号化は借ります。
  署名は間違えればテストで落ちますが、 **暗号化は間違っていても動いてしまい**、
  弱いまま運用に乗る危険があるためです。
- **引き換えに失うもの** — フラグを入れると依存が 14 増えます（59 → 73）。

## 31. ルートモデルバインディングは作らず、1 行で読む

- **決めたこと** — 引数に型を書くと勝手に読む仕組み（`fn show(Post $post)`）は作らない。
  代わりに `req.model::<Post>("post").await?` を用意する。無ければ 404。
- **理由** — 引数の型からパス引数を推測することになり、名前の付け方が崩れると当たりません。
  この書き方なら、 **どの引数でどの型を読むかがその行に書いてあります。**

## 32. キャッシュの鍵は、安全な文字だけそのままファイル名にする

- **決めたこと** — `FileCache` のファイル名は、英数字と `.` `-` `_` だけの鍵なら鍵そのまま
  （`:` は `~` に置き換え）。ほかの文字が入れば SHA-256 の 16 進にする。
- **理由** — `storage/framework/cache/` を見れば何が入っているか分かるようにしたいのですが、
  日本語やパス区切りが入った鍵をそのまま使うとファイル名が壊れます。両方を混ぜました。
- **引き換えに失うもの** — 鍵に記号が入ると、ファイル名からは中身が分からなくなります。

## 33. ファイルの置き場所は、組み立てる前に断る

- **決めたこと** — `Storage` に渡すパスのうち、`..`・絶対パス・`:` を含むものはエラーにする。
- **理由** — 利用者の入力がそのままパスになる画面を書けるので、`../../.env` を防ぐ必要があります。
  組み立てた後に確かめる形だと、まだ無いファイルで `canonicalize` が失敗します。先に断るほうが確実です。

## 34. キューは DB の `jobs` 表だけ。取り出しはトランザクションの中

- **決めたこと** — ジョブは `jobs` 表に入れる（`sqlite` が必要）。
  取り出しは `DB::begin()` の中で「選ぶ → `reserved_at` を立てる」を続けて行う。
  再挑戦の待ちは 10 / 20 / 40 / 80 / 160 / 320 秒。既定 3 回で諦め、`failed_jobs` に移す。
- **理由** — トランザクションの中で押さえないと、worker を 2 つ動かしたときに
  同じジョブを両方が処理します。倍々にするのは Laravel と同じ考え方で、
  上限を付けたのは次の挑戦が何時間も先にならないようにするためです。
- **引き換えに失うもの** — キューは `sqlite` が無いと使えません。
  Redis と比べると 1 秒あたりの処理数は劣ります。
- **その後** — 取り出しをトランザクションから 2 文の比較交換に変えました（判断 75）。
  題名の「トランザクションの中」はもう当てはまりません。

## 35. ジョブと聞く側は 1 つの形にそろえる

- **決めたこと** — `app/Jobs/*.rs` と `app/Listeners/*.rs` の中身は
  `pub async fn handle(payload: String) -> Result<()>` だけ。中身は自分で `from_str` する。
- **理由** — Laravel のジョブはクラスで好きな引数を取れますが、Rust に継承はありません。
  型を自由にすると、名前から呼び出す側（生成コード）が型を知らないため呼べません。
  `String` にしたのは、生成コードがジョブを `tokio::spawn` に渡すためです（`&str` は渡せません）。
- **引き換えに失うもの** — 中身の形が違っていても、実行して初めて分かります。

## 36. スケジューラは cron の式を解さない

- **決めたこと** — 間隔は `Every::{Minute, Minutes(n), Hour, Day, Seconds(n)}` の 5 つ。
  `schedule:run` を 1 分ごとに外から呼ぶ。最後に動かした時刻はキャッシュに置き、 **動かす前に**書く。
- **理由** — Laravel も cron には 1 行だけ登録して、中の判定はアプリが行います。
  式を解析しても得るのは「毎週月曜の 3 時」のような指定で、いまは要りません。
  時刻を先に書くのは、長くかかる処理を二重に走らせないためです。
- **引き換えに失うもの** — 「毎週月曜」「毎月1日」のような指定ができません。

## 37. イベントの登録は起動時だけ

- **決めたこと** — `with_events(|e| e.listen("名前", 関数))` で登録する。
  `app/Listeners/*.rs` は自動では登録しない。
- **理由** — 起動後は読むだけにして、ホットパスでロックを取らないためです。
  どのイベントを誰が聞くかが `bootstrap/app.rs` の 1 か所で分かります。
- **採らなかった案** — ファイル名からイベント名を決めて自動登録する。
  1 つの聞く側が複数のイベントを聞けなくなります。

## 38. メールは `log` と `array` の 2 つ。SMTP は入れない

- **決めたこと** — 送り先は `log`（`storage/logs/mail.log`）と `array`（テスト用）。
  差し替えられるように `Mailer` トレイトは用意する。
- **理由** — SMTP は TLS が前提で、TLS を自前で書くのは無理です。
  `lettre` を入れると依存が約 40 増えるため、形だけ決めて判断を先に延ばしました。
- **引き換えに失うもの** — **本当のメールは送れません。**
  パスワードの再設定もログに出すところまでです。

## 39. 多言語の文字はビルド時に読む。TOML の読み取りは自前

- **決めたこと** — `resources/lang/<言語>.toml` を `bengara-build` がビルド時に読み、
  `&'static` の表にする。実行時にファイルを読まない。
  TOML の読み取りは `bengara-build` の中に最小のものを書く（`[節]` と `鍵 = "値"` だけ）。
- **理由** — 本番に置くのは実行ファイルと `.env` と `storage/` だけ、という約束（判断 17）を守るためです。
  `bengara-build` は依存を持たない決まりなので、`toml` クレートは入れられません。
- **引き換えに失うもの** — 文字を直すには再ビルドが必要です
  （`cargo:rerun-if-changed` を出すので `cargo build` が自動で走り直します）。
  数値・真偽・配列・複数行の文字列は読みません。

## 40. 自作コマンドは説明を必須にする

- **決めたこと** — `app/Console/Commands/*.rs` には `pub const DESCRIPTION: &str` と
  `pub async fn handle(args: &[String]) -> Result<()>` の両方が必要。
  ファイル名からコマンド名を作る（`SendReport.rs` → `send-report`）。
- **理由** — 説明を任意にすると `cargo artisan list` に名前だけが並び、一覧が読めなくなります。
  引数の解析（Laravel の `$signature`）は、手間に対して得るものが少ないので作っていません。

## 41. 通知と放送は作らない

- **決めたこと** — Laravel の `Notification` と `Broadcasting` に当たるものは作らない。
- **理由** — 通知は複数の送り先に同じ中身を送る仕組みですが、いまは送り先が `Mail` だけなので
  `Mail` と変わりません。放送は WebSocket が前提で、別の仕組みが必要になります。

## 42. 基準ディレクトリが決まらなければ起動しない

- **決めたこと** — `APP_BASE_PATH`（絶対パスのみ）→ `CARGO_MANIFEST_DIR` →
  実行ファイルの隣 → カレントディレクトリ の順に見て、最初に決まったものを使う。
  3 と 4 は **`.env` か `storage/` があるときだけ**使う。どれも決まらなければ起動を止める。
- **理由** — カレントディレクトリに落とすと、別の場所から起動したときに `.env` が読まれず、
  空の `storage/` が作られ、設定なしで動き出します。本番でこれが起きると、
  セッションも DB も見当違いの場所を向きます。
  目印を見るのが肝です。目印なしでディレクトリを採ると、`cargo run` で `target/debug/` が基準になります。
- **引き換えに失うもの** — `.env` も `storage/` も無い状態では起動できません。これは狙った動きです。

## 43. `storage/` の場所は外に出せる。`public/` は出せない

- **決めたこと** — `APP_STORAGE_PATH`（ **絶対パスのみ**）で `storage/` を動かせる。
  相対パスは起動を止める。`public/` の場所は変えられない。
- **理由** — プロセスを2つ以上動かすとき、全プロセスが同じ `storage/` を見る必要があります。
  相対パスだと起動の仕方で場所が変わります。
  `public/` はリリースビルドでバイナリに入るので、外の場所を指す意味がありません。

## 44. 停止の動きは全 OS で同じにし、上限時間で打ち切る

- **決めたこと** — 受け付ける合図は OS ごとに増やす（Windows は Ctrl+C・Ctrl+Break・
  コンソールを閉じる操作・ログオフ・シャットダウン）。受け取った後は全 OS で同じ順序。
  上限は `APP_SHUTDOWN_TIMEOUT`（既定 30 秒、`0` は無制限）。打ち切ったら警告を出す。
- **理由** — 受け付ける合図は OS の事情で違ってよいのですが、その後が違うと運用の手順が分かれます。
  上限を入れたのは、終わらないリクエストが1本あるだけで無停止更新が止まるのを防ぐためです。
  axum に打ち切りの仕組みは無いので、待つのをやめることで打ち切ります。
- **引き換えに失うもの** — 30 秒を超えるリクエストは切られます。長い処理はキューへ。
  Windows のサービス停止要求は受け取れません（サービスとして登録する仕組みが要ります）。

## 45. `migrate` 系は DB の札で排他する

- **決めたこと** — 表を変えるコマンドは、実行の前に `migration_locks` 表へ1行入れる。
  入らなければ止める。残った札は `migrate:unlock` で外す。
  札には誰が取ったか（ホスト名とプロセス番号）と時刻を書く。
- **理由** — プロセスを2つ以上動かす前提なので、デプロイで両方が `migrate` を叩く事故が起きます。
  主キーを固定の値にすると2行目は入らないので、 **DB の一意制約をそのまま排他に使えます。**
  SQLite に advisory lock が無いので、この形にしました。
- **引き換えに失うもの** — 途中で落ちると札が残り、次の `migrate` が止まります。 **時間で自動には外しません。**
  長いマイグレーションの最中に二重に走る恐れがあるためです。

## 46. `public/` はリリースビルドのときだけバイナリに埋め込む

- **決めたこと** — `bengara-build` が `PROFILE` を見て、リリースビルドのときだけ
  `include_bytes!` で `public/` を入れる。デバッグビルドではディスクから読む。
  配信は埋め込みが優先。鍵の区切りは常に `/`。
  1ファイル 8 MiB・合計 32 MiB を超えたら `cargo:warning` を出す（止めない）。
- **理由** — 本番に置くのは実行ファイルと `.env` と `storage/` の3つだけ、という約束を守るためです。
  デバッグで埋め込まないのは、CSS を直すたびに再ビルドするのが苦しいからです。
  鍵を `/` に固定するのは、Windows で作ったバイナリを Linux で動かしても同じ鍵で引けるようにするためです。
- **引き換えに失うもの** — 圧縮の事前生成・範囲リクエストはありません。
  ファイル数が多いとコンパイルが重くなります。
- **後から足したもの** — `ETag` と 304（決定記録 #61）。

## 47. `storage/app/public/` は `/storage/...` で直接配信する

- **決めたこと** — `storage/app/public/` を `/storage/...` で配信する。
  `storage:link`（シンボリックリンク）は作らない。
  探す順番は「ルート → `/storage/...` → 埋め込んだ `public/` → ディスクの `public/`」。
  置き場所の外を指すパスは **404** にする。
- **理由** — `storage:link` は Windows でシンボリックリンクを作るので、管理者権限か
  開発者モードが要ります。OS で動きが変わる仕組みは避けました。
  ルートを先に見るのは、`/storage/...` に自分のルートを書いて認可を挟めるようにするためです。
  404 にするのは、攻撃の試みに「何が起きたか」を教えないためです。
- **引き換えに失うもの** — 頭のパス（`/storage/`）は変えられません。
  大量の画像を配るなら、前段のプロキシから直接見てください。

## 48. `about` は秘密を出さない

- **決めたこと** — `cargo artisan about` でいまの設定と置き場所を出す。 **`APP_KEY` の値は出さない。** 設定されているかどうかだけを出す。
- **理由** — 本番で困ったとき、まず知りたいのは「どこを見ているのか」です。
  鍵を出すと、画面の共有やログの貼り付けで漏れます。1回でも漏れたら入れ替えが必要になります。

## 49. CSRF の確認を外すのは、Cookie で認証しない API だけ

- **決めたこと** — `VerifyCsrfToken::except` で外すのは、Cookie を使わない API だけにする。
  `/api/*` のようにまとめて外さない。
- **理由** — `StartSession` は全ルートに掛かるので、`/api/*` も Cookie で認証されます。
  そこで CSRF だけ外すと、別のサイトから Cookie に便乗して書き込めます。
  `SameSite=Lax` が支えているだけの状態になります。

## 50. モデルの保存は、トランザクションを明示する

- **決めたこと** — `save_using(&tx)` / `delete_using(&tx)` / `fresh_using(&tx)` を用意する。
  `save()` / `delete()` / `fresh()` は既定の接続を使う。
  `#[derive(Model)]` は **自動採番の整数の主キー専用**。それ以外はコンパイルエラー。
- **理由** — `:memory:` の DB は接続が1本なので、トランザクションの中で `save()` を呼ぶと
  接続が空くのを待ち続けて固まります。ファイルの DB では、気づかないうちに
  トランザクションの外に書かれます。
  整数以外の主キーは値が `insert` に乗らないので、動かないことをコンパイルの時点で伝えます。

## 51. `count()` は束ねたときグループの数を返す

- **決めたこと** — `group_by` が付いているときの `count()` は副問い合わせにしてグループの数を返す。
  `distinct` のときは重なりを除いた数。`sum` / `avg` / `min` / `max` は `group_by` と併用できない。
- **理由** — 以前は最初のグループの件数が返っていました。`paginate` の総数も同じでした。
  黙って違う数を返すのが一番困ります。

## 52. クエリビルダは列名と演算子を確かめる

- **決めたこと** — `order_by` / `order_by_desc` / `group_by` / `having_op` の列名は英数字と `_` `.` だけ。
  演算子は許可一覧で照合する。外れたら実行のときにエラー。式は `order_by_raw` / `where_raw` / `having_raw`。
  `update` / `delete` に `join` と `limit` / `offset` を付けるとエラー。
- **理由** — `select` に式を書けるようにしてある逃げ道が、並び順にも効いていました。
  外から来た文字列を `order_by` に渡せる作りは危ないです。
  `limit(1).update(..)` が黙って全件を書き換えていたのも直しました。
- **その後** — 検査の範囲を条件・結合・書き込みのすべてに広げました（判断 65）。
  できない指定をエラーにする範囲も広げました（判断 66）。

## 53. ルートの URL を作るときはパス引数を符号化する

- **決めたこと** — `route_with()` はパス引数をパーセント符号化する（`/` も `%2F`）。
  末尾全取り（`{*path}`）のときだけ `/` を残す。
  `signed_url()` は `?` `#` と非 ASCII を含むパスを断る。
- **理由** — 照合する側は符号化されたパスで見ます。作る側だけ生のままだと、
  ルートの形が変わったり、署名が黙って合わなくなったりします。

## 54. `APP_KEY` は長さを確かめ、用途ごとに別の鍵を作る

- **決めたこと** — `APP_KEY` は 64 文字以上を必須にする。
  使うときは `hmac_sha256(APP_KEY, 用途名)` で用途ごとの鍵を作る。
  用途名は `bengara:session` / `bengara:signed-url` / `bengara:encryption`。
- **理由** — 短い鍵でも HMAC は計算できてしまうので、入口で断るしか気づく手段がありません。
  同じ鍵を使い回すと、どれか1つに署名を作らせる隙ができたときに他へ波及します。
- **注意** — これを入れた時点で、いまあるセッション・暗号文・配布済みの署名付き URL は無効になります。
  `APP_KEY` を作り直したときと同じです。

## 55. 共通のミドルウェアは 404 と 405 にも通す

- **決めたこと** — 共通のミドルウェアを、ルートに当たらなかったリクエストにも通す。
  ただし `VerifyCsrfToken` は、ルートが無いときは確かめない。
- **理由** — Laravel は 404 でも共通のミドルウェアを通します。
  いっぽうで、無いページへの POST が 419 になるのは分かりにくいので、
  守る対象のルートが無いときは確かめません。
- **その後** — ルートが無いときはトークンも用意しない形にしました（判断 63）。

## 56. 回数の制限は接続元のアドレスで数える

- **決めたこと** — `Throttle` はつないできた相手のアドレスで数える。
  `X-Forwarded-For` と `X-Real-IP` は `TRUSTED_PROXIES` に載っている相手からのものだけ見る。
  空ならどちらも見ない。範囲指定（CIDR）は書けない。
  鍵の後半は **ルート名**にする（名前が無いルートだけパス。決定記録 #62）。
- **理由** — 以前は `X-Forwarded-For` をそのまま鍵にしていたので、偽装すれば制限が無制限に回せました。
  逆にヘッダーが無いと全員が同じ枠を共有し、1人が使い切ると全員が締め出されました。

## 57. `min` / `max` / `between` は、数か文字数かを規則で決める

- **決めたこと** — `numeric` か `integer` が付いている項目だけ値で比べる。
  付いていなければ文字数で比べる。Laravel と同じ。
- **理由** — 以前は「数として読めるか」で切り替えていたので、
  `password=9` が `min:8`（8 文字以上のつもり）を通っていました。
  規則の書き方と挙動が結びついていないと、読んでも分かりません。

## 58. 空文字にも規則を当てる

- **決めたこと** — 検査を飛ばすのは「項目が送られてこなかった」ときと `nullable` のときだけ。
- **理由** — 以前は空文字も飛ばしていたので、`role=""` が `in:admin,user` を通っていました。

## 59. 利用者を指定してセッションを切れるようにする

- **決めたこと** — `Auth` に `logout_other_devices()` / `logout_all_devices()` / `logout_user(id)` を足す。
  置き場所側は `SessionStore` に `destroy_for_user` と `destroy_for_user_except`（既定の実装つき）。
  `Session::regenerate()` は CSRF トークンも作り直す。
- **理由** — `logout()` はいまのセッションだけを切ります。パスワードを変えても、
  盗まれたセッションが期限まで生き残ります。
  パスワードの再設定では本人がログインしていないので、利用者を指定する口が要ります。

## 60. キャッシュとスケジューラの置き場所を確実にする

- **決めたこと** — キャッシュの一時ファイルは鍵ごとに別の名前にする。
  鍵に大文字が含まれるときはハッシュにする。
  `CacheStore` に `increment` / `has` / `prune` を足し（既定の実装つき）、数は置き場所側で排他する。
  スケジューラの前回時刻はキャッシュではなく `storage/framework/schedule/` のファイルに置く。
  キューは `retry_after`（既定 90 秒）で、予約されたまま残ったジョブを取り直す。
- **理由** — 一時ファイルの名前が拡張子の置き換えだったので、
  `test.put` と `test.count` が同じ `test.tmp` を使い、値が混ざっていました。
  大文字小文字を区別しない OS では `User:1` と `user:1` が同じファイルになっていました。
  数は読んで書くだけだったので、同時に呼ばれると数を落としていました。
  前回時刻をキャッシュに置くと、`CACHE_DRIVER=memory` のとき毎分走っていました。
  ワーカーが異常終了すると、処理中だったジョブが二度と処理されませんでした。
- **その後** — 置き場所の印を `~` / `+locks` / `.+tmp.` にしました（判断 71）。
  キューの取り出しを 2 文にしました（判断 75）。タスクごとの錠を足しました（判断 76）。

## 61. 静的ファイルに `ETag` と 304 を付ける

- **決めたこと** — `public/`・埋め込み・`/storage/` の応答に、弱い `ETag` と
  `Cache-Control: public, max-age=0, must-revalidate` を付ける。`If-None-Match` が合えば 304 を返す。
  `HEAD` ではファイルを読まず `content-length` だけを返す。
  ETag の中身は、ディスクなら「長さ＋更新時刻（秒）」、埋め込みなら「長さ＋中身のハッシュ」。
- **理由** — 判断 46（`public/` の埋め込み）では「前段のプロキシに任せる」としていました。
  ですが前段を置かない構成でも使えることを売りにしているので、
  リロードのたびに全部を送り直すのは重すぎます。304 だけなら依存も増えません。
- **採らなかった案** — 強い `ETag`（中身のハッシュ）。ディスクのファイルを毎回読むことになり、
  304 で読まずに済ませるという目的と矛盾します。
- **割り切り** — 同じ秒の内に同じ長さで書き換えると ETag が変わりません。
  本番では名前にハッシュを付けたファイル名を使ってください。
  `Last-Modified` と範囲リクエストは引き続きありません。

## 62. 回数の制限はルート名で数える

- **決めたこと** — `Throttle` の鍵を「相手とルート名の組」にする。
  ルートに名前が無いときだけパスで数える。
  置き場所が天井を超えたときは、`count` の多い鍵を残して捨てる。
- **理由** — パスで数えると、`/api/items/{id}` のようなルートで相手が値を変えるだけで
  枠を無限に増やせました。さらに、古い順に捨てていたので、
  鍵を大量に作れば `/login` の計数を押し出してやり直せました。
- **採らなかった案** — 鍵の数に上限を設けず全部覚える。記憶がいくらでも増えます。

## 63. CSRF を外すのはルート名で指定する

- **決めたこと** — `VerifyCsrfToken::except_route(pattern)` を足し、こちらを勧める。
  `except(pattern)`（パス）は、名前の無いルートを外すときのために残す。
  あわせて、ルートに当たらないリクエストでは**トークンも用意しない**。
- **理由** — パスでの指定はルート表と二重の管理になり、`*` の置き場所を間違えると
  思っていない所まで外れます。名前なら、あとから増えたルートが勝手に外れることもありません。
  トークンを用意しないのは、Cookie を持たない人が無いページを叩くたびに
  セッションのファイルが 1 つ増えていたからです。
- **採らなかった案** — `except` を消す。公開 API を壊さないため残しました。

## 64. 登録していないミドルウェアの名前は起動時に止める

- **決めたこと** — `.middleware("admin")` の `admin` が登録されていなければ、起動時に止める。
  `with_middleware(...)` を一度も書いていないときも同じ。
- **理由** — 以前は `with_middleware(...)` を書いていないときだけ検査を飛ばしていました。
  `init` が作ったままのプロジェクトで `.middleware("admin")` と書くと、**黙って素通し**になり、
  管理画面が誰にでも見えました。起動時に止めるのは、本番に出る前に気づくためです。
- **採らなかった案** — 警告だけ出して動かす。気づかずに本番へ出せてしまいます。

## 65. 列名と表名の検査を、条件・結合・書き込みのすべてに広げる

- **決めたこと** — `where_` 系すべて・`join` / `left_join`（表名・両側の列名・演算子）・
  `insert` / `insert_many` / `insert_get_id_as` / `update` の列名・`DB::table(...)` の表名を検査する。
  英数字は **Unicode** で見る（日本語の列名も通る）。
  引用符を含む名前は式として素通しせず、`""` に逃がしてくくる。
- **理由** — 判断 52 では `order_by` 系だけを検査していました。
  条件側は素通しだったので、外から来た文字列を `where_` に渡す書き方が通りました。
  引用符を素通ししていたのは、引用符を 1 つ混ぜるだけで検査を抜けられる道でした。
- **採らなかった案** — ASCII の英数字だけに絞る。日本語の列名が書けなくなります。
  `"` `;` `(` `-` と空白は Unicode でも英数字ではないので、検査の強さは変わりません。

## 66. 組み立てた SQL に入らない指定はエラーにする

- **決めたこと** — 次をエラーにする。
    - `group_by` の無い `having`
    - `update` / `delete` / `truncate` に付けた `group_by` / `having` / `distinct`
    - 条件（`where_` など）を付けた `truncate`

  `order_by` だけは黙って無視する（SQL に入らなくても、当たる行が変わらないため）。
  `distinct` 付きの集計は `関数(distinct 列)` にする（列が式や `*` のときはエラー）。
- **理由** — 判断 51 の続きです。指定が黙って落ちると、**全件に当たっていることに気づけません。**
  条件付きの `truncate` は、とくに危ないのに黙って全件消えていました。
- **採らなかった案** — 黙って無視する。消えてから気づくことになります。

## 67. 中身が消えるコマンドは `migrate:reset` と `migrate:refresh` も本番で止める

- **決めたこと** — `APP_ENV=production` で `--force` が無いと止まるコマンドを 4 つにする。
  `migrate:reset` / `migrate:refresh` / `migrate:fresh` / `db:wipe`。
- **理由** — `reset` と `refresh` は名前に「消す」と書いていませんが、`down` を流すので中身は消えます。
  名前で選んでいたので漏れていました。
- **採らなかった案** — 名前に `fresh` や `wipe` を含むかで判定する。同じ漏れを繰り返します。

## 68. 知らないバリデーション規則は 500 にする

- **決めたこと** — 知らない規則名は、項目ごとの 422 ではなく開発者向けのエラー（500）にする。
  メッセージに使える規則名の一覧を出す。
  あわせて、数値として読めない値のときは `min` / `max` / `between` / `size` は何も言わない。
  `numeric` は `inf` / `NaN` / `1e400` を通さない。
- **理由** — `requiredd` のような書き間違いは、**利用者の入力の問題ではありません。**
  422 で返すと、利用者には意味の分からない理由が出て、開発者は気づきません。
  `min` を黙らせるのは、`abc` を `integer|min:5` で検査したときに理由が 2 件になり、
  「5 文字以上にしてください」が混ざって分かりにくかったからです。
- **採らなかった案** — 知らない規則を無視して通す。規則を書いたつもりで何も検査されません。

## 69. 覚えない入力の名前は語の単位で突き合わせる

- **決めたこと** — `old()` が覚えない名前の判定を、部分一致から**語の単位**に変える。
  名前を `_` `-` `.` 空白と大文字の境目で語に区切り、その語が一覧にあるかを見る。
  一覧から `api_key` / `private_key` を外し（`key` の語で当たる）、`credentials` と `signature` を足す。
  アクセスログのクエリの値も、同じ判定で `***` に伏せる。
- **理由** — 部分一致だったので、`keyword`（`key`）・`opinion`（`pin`）・`shipping_address`（`ssn`）
  などが黙って覚えられず、検査に落ちたときに入力欄が空になりました。
  ログを伏せるのは、署名付き URL をログに出すと署名がそのまま残るからです。
- **採らなかった案** — 完全一致だけにする。`new_password_confirmation` が漏れます。

## 70. `Hash::check` は平文の長さに上限を置く

- **決めたこと** — 照合に渡せる平文を 1024 バイトまでにする。超えたら計算せずに偽を返す。
  `Hash::make` には上限を置かない。
- **理由** — PBKDF2 の計算量は長さに左右されませんが、入口の `sha256` は長さに比例します。
  2 MB の文字列を送るだけで CPU を使わせられました。
  人が覚えて入力するパスワードは、これより桁違いに短いです。
- **採らなかった案** — Laravel と同じく上限を置かない。入口で `max:1024` を付けるよう案内します。

## 71. 置き場所の印は、鍵として現れない文字で付ける

- **決めたこと** — キャッシュのハッシュ名の頭に `~` を付ける。錠の置き場所を `+locks/` にする。
  一時ファイルを `<鍵>.+tmp.<プロセス番号>.<連番>` にする。
- **理由** — 判断 60 の続きです。印が普通の文字だと、鍵と見分けられません。
  `locks` という鍵が使えず、`report.2024.12` のような鍵が一時ファイルと取り違えられました。
  `+` を選んだのは、**大文字小文字を区別しない OS でも取り違えないため**です
  （`LOCKS` を鍵にされると `locks` とぶつかります）。
  `~` を選んだのは、`:` がファイル名に使えないからです。
- **採らなかった案** — `LOCKS` のように大文字で印を付ける。NTFS と APFS では区別されません。

## 72. 言語ファイルは `resources/lang/<言語>/` も読む

- **決めたこと** — `resources/lang/<言語>.toml` に加えて、`resources/lang/<言語>/<群>.toml` も読む。
  鍵の頭にファイル名が付く。両方を混ぜてもよく、1 つの表にまとまる。
  さらに下のディレクトリは読まず、警告を出す。
  `__with` の置き換えは 1 回の走査にし、差し込んだ値の中の `:名前` は再置換しない。
- **理由** — ディレクトリに分ける形が Laravel 本来の置き方です。
  ファイル 1 枚だと、文が増えたときに分けられませんでした。
  再置換しないのは、利用者が入れた値に `:title` が入っていると
  別の文に差し替わってしまうからです。
- **採らなかった案** — ディレクトリ方式だけにする。いまある `ja.toml` が読めなくなります。

## 73. 自動検出は、中身が変わったときだけ書く

- **決めたこと** — `bengara-build` が生成するコードは、中身が変わったときだけ書き出す。
  無いディレクトリは `rerun-if-changed` に出さず、代わりに親を 1 回だけ見張る。
  入れ子のディレクトリも見張る。`public/` はデバッグビルドでも見張る。
  マイグレーション・シーダー・ジョブ・自作コマンドは入れ子に置ける（1 つの一覧にまとまる）。
  名前がぶつかったら `compile_error!` で知らせる。
- **理由** — 無いディレクトリを `rerun-if-changed` に出すと、Cargo は毎回ビルドスクリプトを走らせます。
  さらに生成コードを毎回書いていたので、関係ない変更でアプリのクレートが丸ごと再コンパイルされました。
  入れ子を見張っていなかったので、`app/Http/Controllers/` の下にファイルを足しても気づきませんでした。
- **採らなかった案** — 入れ子の名前に接頭辞を付ける（`Demo/AdminSeeder` → `demo:admin-seeder`）。
  名前の付け方が置き場所に縛られます。まずは全体で重ならないよう求める形にしました。

## 74. `Storage` は Windows の装置名を全 OS で断る

- **決めたこと** — `nul` `con` `com1` などの装置名（拡張子が付いていても）を、**全 OS で**断る。
  パス要素の末尾が空白か `.` の名前も断る。
- **理由** — Windows では `Storage::put("notes/nul.txt", ...)` が成功を返し、
  読み戻すと 0 バイトになります。**開発（Windows）と本番（Linux）で挙動が変わります。**
  末尾の空白は、Windows が黙って落とすので `a.txt ` と `a.txt` が同じファイルになりました。
- **採らなかった案** — Windows のときだけ断る。開発で通ったものが本番で通らない、
  あるいはその逆になり、気づくのが遅れます。

## 75. キューの取り出しは 2 文の比較交換にする

- **決めたこと** — ジョブの取り出しを、トランザクションではなく
  `select` → 条件付き `update` の 2 文にする。`finish` / `fail` も `reserved_at` を条件に入れる。
  `queue:work` は 2 回目の Ctrl+C で強制終了する（終了コード 130）。
- **理由** — WAL では、トランザクションの中で読んだ行を別のプロセスが書き換えると
  `SQLITE_BUSY_SNAPSHOT` になります。これは再試行の対象にならず、**ワーカーが丸ごと落ちました。**
  `reserved_at` を条件に入れるのは、`retry_after` を超えた処理が
  別のワーカーの行を消してしまわないようにするためです。
- **採らなかった案** — 再試行を自分で書く。2 文にすれば、そもそも衝突しません。

## 76. `schedule:run` はタスクごとに錠を取る

- **決めたこと** — 定期処理は、タスクごとに錠ファイルを取ってから動かす。
  取れなければ「飛ばします」と出して、そのタスクだけ今回は動かさない。
- **理由** — cron の間隔より処理が長引いたとき、同じ処理が重なって走りました。
  2 台で同じ `storage/` を共有する構成でも重なります。
- **採らなかった案** — 錠を時間で自動に外す。長い処理の最中に二重に走ります。

## 77. ログイン後の戻り先は `Session::intended()` で取り出す

- **決めたこと** — `Session::intended()` を足す（読むと消える）。
  戻り先を覚えるのは **302 で転送するときだけ**にする。
  `Authenticate::new()`（401）や、JSON を期待しているリクエストでは覚えない。
- **理由** — 鍵の名前（`bengara_auth_intended`）を利用者に直接読ませていました。
  401 のときに覚えていたのは、使い道が無いのにセッションへ書き込むだけで、
  API への 401 のたびにファイルが増えていました。
- **採らなかった案** — 常に覚える。書き込みが無駄に増えます。

## 78. prelude は毎回出てくるものだけに絞る

- **決めたこと** — `prelude` に入れるのは、ほとんどのファイルで使うものだけ。
  クレートの根（`bengara::`）に出している公開 API と中身をそろえない。
- **理由** — prelude が大きいと、`use bengara::prelude::*;` だけで名前がたくさん入り、
  アプリ側の名前とぶつかります。たまに使うものは `bengara::` から直接書くほうが読めます。
- **採らなかった案** — 根と prelude を同じにする。分かりやすいが、名前の衝突が増えます。
