# 多言語

画面に出す文字を、言語ごとに分けて持つ仕組みです。
このページで、言語ファイルの置き方・文字の引き方・言語の切り替え方が分かります。

文字は `resources/lang/` の TOML ファイルに書きます。
**ビルド時に読み込んで、実行ファイルに入ります。** 文字を変えたら、ビルドし直します。

## 言語ファイルを置く

置き方は 2 通りです。同じ言語で両方を置いてもよく、1 つの表にまとまります。

| 置き方                            | `[x] y = ".."` の鍵 | 言語の名前     | 向くとき                 |
|-----------------------------------|---------------------|----------------|--------------------------|
| `resources/lang/<言語>.toml`      | `x.y`               | ファイル名     | 鍵が少ない。1 枚で見たい |
| `resources/lang/<言語>/<群>.toml` | `<群>.x.y`          | ディレクトリ名 | 群ごとにファイルを分ける |

```toml
# resources/lang/ja.toml
[messages]
welcome = "ようこそ"
greeting = "こんにちは、:name さん"

[posts]
created = "記事を作りました"
```

```toml
# resources/lang/en.toml
[messages]
welcome = "Welcome"
greeting = "Hello, :name"
```

下が Laravel と同じ置き方です。ファイル名が鍵の頭に付きます。

```toml
# resources/lang/ja/messages.toml — 鍵は messages.welcome になります
welcome = "ようこそ"
```

次のものは読みません。

| 置いたもの                              | 例                       | 警告         |
|-----------------------------------------|--------------------------|--------------|
| `<言語>/` より下のディレクトリ          | `ja/admin/menu.toml`     | 出る         |
| 名前に `.` か空白が入った控え           | `ja.old/`、`ja copy.toml` | 出る        |
| `.` で始まるもの                        | `.git/`                  | 出ない       |

**控えは `resources/lang/` の外に置いてください。**

## 使う

```rust
use bengara::prelude::*;

__("messages.welcome");                               // ようこそ
__with("messages.greeting", &[("name", "アリス")]);   // こんにちは、アリス さん
```

鍵は `節.鍵` の形です。`__` は Laravel と同じ名前です。

### 鍵が無いとき

**鍵の文字がそのまま返ります。** 落ちません。画面を見れば、どの鍵が抜けているか分かります。

```rust
__("messages.ない鍵");   // => "messages.ない鍵"
```

探す順番は次のとおりです。

1. いまの言語（`Lang::current()`）
2. `APP_FALLBACK_LOCALE` の言語
3. 鍵そのもの（警告をログに出す）

同じ鍵の警告は、続けては出しません。抜けが 1 つあっても、リクエストのたびにログが増えません。
無い鍵が多いときは、同じ鍵の警告がもう一度出ることがあります。

### 差し替え

文の中の `:名前` を、渡した値に差し替えます。

```toml
greeting = "こんにちは、:name さん"
count = ":total 件のうち :done 件が終わりました"
name_both = ":name（:name_kanji）"
```

```rust
__with("messages.count", &[("total", "10"), ("done", "3")]);
// => "10 件のうち 3 件が終わりました"
```

| 決まり                               | 内容                                                          |
|--------------------------------------|---------------------------------------------------------------|
| 長い名前から当てる                   | `:name` と `:name_kanji` が並んでいても壊れない               |
| 差し込んだ値は見直さない             | 値の中に `:名前` があっても、差し替えない                     |
| エスケープしない                     | HTML に出すときは `escape_html` を通す                        |
| 渡していない名前                     | `:名前` のまま残る                                            |
| 空の名前（`("", 値)`）               | 無視する                                                      |

```rust
__with("messages.greeting", &[("name", "田中 :title"), ("title", "部長")]);
// => "こんにちは、田中 :title さん"。値の中の `:title` は置き換わりません
```

## 言語を切り替える

```
APP_LOCALE=ja
APP_FALLBACK_LOCALE=ja
```

| 設定                  | 既定 | 役割                           |
|-----------------------|------|--------------------------------|
| `APP_LOCALE`          | `ja` | 最初の言語                     |
| `APP_FALLBACK_LOCALE` | `ja` | その言語に鍵が無いときに見る先 |

途中で変える方法は 2 つです。

| 書き方                   | 効く範囲                     | 使う場面                       |
|--------------------------|------------------------------|--------------------------------|
| `Lang::with(言語, 処理)` | 渡した処理の中だけ           | **リクエストごとに変えるとき** |
| `Lang::set(言語)`        | **プロセス全体**（戻らない） | 起動時に 1 回だけ決めるとき    |

`Lang::with` は、処理が終わると元の言語に戻ります。

```rust
pub async fn show(req: Request) -> Result<Response> {
    let locale = req.query("locale").unwrap_or_else(Lang::current);

    Lang::with(locale, async {
        json(&bengara::serde_json::json!({ "welcome": __("messages.welcome") }))
    })
    .await
}
```

**`Lang::set` をリクエストの中で呼ばないでください。**
プロセス全体に効くので、同時に来た別のリクエストの言語も変わります。
テストで呼ぶときは `exclusive()` の札を取ります（[testing.md](testing.md)）。

いまの状態は、次の 3 つで分かります。

```rust
Lang::current();        // "ja"
Lang::available();      // ["en", "ja"]
Lang::has("fr");        // false
```

コマンドでも見られます。

```sh
cargo artisan lang:list
```

```
いまの言語: ja
  en
  ja
```

## 読める TOML の範囲

TOML の全部は読みません。読めるのは次の形だけです。

| 読める                              | 読めない                        |
|-------------------------------------|---------------------------------|
| `[節]`。`[a.b]` は `a.b.鍵` になる  | 配列（`[1, 2]`）                |
| `鍵 = "値"` / `鍵 = '値'`           | 引用符なしの値（数・真偽）      |
| `"` の中の `\n` `\t` `\r` `\\` `\"` | 複数行の文字列（`"""`）         |
| `#` から行末のコメント              | インラインのテーブル（`{ … }`） |

- 節の外に書いた鍵は、そのままの鍵になります（`title = "x"` → `title`）。
- **鍵と節の名前に使えるのは、英数字と `_` `-` `.` だけです。** `.` は端に置けず、続けても書けません。
- `\` をそのまま出したいときは `\\` と書くか、`'` でくくります（`'...'` の中は `\` を解釈しません）。
- 先頭の BOM（メモ帳が付ける目印）は読み飛ばします。

### ビルドが止まる書き方

**読めない行があると、ビルドが止まります。** 行番号と理由が出るので、その行を直してください。

| 書き方         | 理由                           |
|----------------|--------------------------------|
| `[a] b = "c"`  | 1 行に節と鍵が混ざっている     |
| `"a.b" = "x"`  | 引用符でくくった鍵は読めない   |
| `a = "x""y"`   | 引用符が途中で閉じている       |
| `[a.]`         | `.` が端にある                 |
| `a = "あ\qい"` | `\q` は使えない書き方          |
| `a = "abc\"`   | 値の文字列が閉じていない（`\"` は中の `"` と読む）。`\` で終わる値は `"abc\\"` と書く |
| `a = 10`       | 値を引用符でくくっていない     |

**同じ鍵を 2 回書いても、ビルドが止まります。** 言語の名前と、鍵が書かれていた 2 つのファイルが出ます。
`ja.toml` と `ja/` の両方に同じ鍵を書いたときも同じです。

```
`ja` に鍵 `messages.welcome` が2回書かれています: resources/lang/ja.toml と resources/lang/ja/messages.toml
```

## できないこと

| できないこと                               | 代わりにすること                                |
|--------------------------------------------|-------------------------------------------------|
| 数で文を変える（`trans_choice`）           | 鍵を分ける（`one` / `many` など）               |
| JSON の言語ファイル                        | TOML で書く                                     |
| 実行中に言語ファイルを読み直す             | ビルドし直す                                    |
| 入力の検査（`validate`）の文を言語で変える | 自分で確かめて、`__()` で文を作る               |

`[validation]` の節を書いても、検査のメッセージは変わりません（[validation.md](validation.md)）。

まだ無い機能の一覧は [backlog.md](backlog.md) にあります。
