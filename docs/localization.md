# 多言語

画面に出す文字を、言語ごとに分けて持つ仕組みです。

文字は `resources/lang/` の TOML ファイルに書きます。
**ビルド時に読み込んで、実行ファイルに入れます。** 文字を変えたら、ビルドし直します。

## 使う

```rust
use bengara::prelude::*;

__("messages.welcome");                               // ようこそ
__with("messages.greeting", &[("name", "アリス")]);   // こんにちは、アリス さん
```

- 鍵は `節.鍵` の形です。`__` は Laravel と同じ名前です。
- **鍵が無いときは、鍵の文字がそのまま返ります**（`"messages.ない鍵"`）。落ちないので、画面を見れば抜けている鍵が分かります。

探す順番は次のとおりです。

1. いまの言語（`Lang::current()`）
2. `APP_FALLBACK_LOCALE` の言語
3. 鍵そのもの（ログに警告。同じ鍵の警告は続けては出さない）

### 差し替え

文の中の `:名前` を、渡した値に差し替えます。

```toml
count = ":total 件のうち :done 件が終わりました"
```

```rust
__with("messages.count", &[("total", "10"), ("done", "3")]);
// => "10 件のうち 3 件が終わりました"
```

- 長い名前から当てます。`:name` と `:name_kanji` が並んでいても壊れません。
- 差し込んだ値の中の `:名前` は、差し替えません。
- 渡していない名前は `:名前` のまま残ります。
- **エスケープしません。** HTML に出すときは `escape_html` を通してください。

## 言語ファイルを置く

置き方は 2 通りです。同じ言語で両方を置くと、1 つにまとまります。

| 置き方                            | `[x] y = ".."` の鍵 | 言語の名前     |
|-----------------------------------|---------------------|----------------|
| `resources/lang/<言語>.toml`      | `x.y`               | ファイル名     |
| `resources/lang/<言語>/<群>.toml` | `<群>.x.y`          | ディレクトリ名 |

```toml
# resources/lang/ja.toml
[messages]
welcome = "ようこそ"
greeting = "こんにちは、:name さん"
```

2 つめが Laravel と同じ置き方です。ファイル名が鍵の頭に付きます。

```toml
# resources/lang/ja/messages.toml — 鍵は messages.welcome になります
welcome = "ようこそ"
```

次のものは読みません。控えは `resources/lang/` の外に置いてください。

- `<言語>/` より下のディレクトリ（`ja/admin/menu.toml`）。警告が出ます。
- 名前に `.` か空白が入った控え（`ja.old/`、`ja copy.toml`）。警告が出ます。
- `.` で始まるもの（`.git/`）。

## 言語を切り替える

| 設定                  | 既定 | 役割                           |
|-----------------------|------|--------------------------------|
| `APP_LOCALE`          | `ja` | 最初の言語                     |
| `APP_FALLBACK_LOCALE` | `ja` | その言語に鍵が無いときに見る先 |

途中で変える方法は 2 つです。

| 書き方                   | 効く範囲                 | 使う場面                    |
|--------------------------|--------------------------|-----------------------------|
| `Lang::with(言語, 処理)` | 渡した処理の中だけ       | リクエストごとに変えるとき  |
| `Lang::set(言語)`        | プロセス全体（戻らない） | 起動時に 1 回だけ決めるとき |

```rust
pub async fn show(req: Request) -> Result<Response> {
    let locale = req.query("locale").unwrap_or_else(Lang::current);

    Lang::with(locale, async {
        json(&bengara::serde_json::json!({ "welcome": __("messages.welcome") }))
    })
    .await
}
```

**`Lang::set` をリクエストの中で呼ばないでください。** 同時に来た別のリクエストの言語も変わります。
テストで呼ぶときは `exclusive()` の札を取ります（[testing.md](testing.md)）。

いまの状態は次の 3 つで分かります。`cargo artisan lang:list` でも見られます。

```rust
Lang::current();        // "ja"
Lang::available();      // ["en", "ja"]
Lang::has("fr");        // false
```

## 書ける TOML

TOML の全部は読みません。読めるのは次の形だけです。

| 読める                              | 読めない                        |
|-------------------------------------|---------------------------------|
| `[節]`。`[a.b]` は `a.b.鍵` になる  | 配列（`[1, 2]`）                |
| `鍵 = "値"` / `鍵 = '値'`           | 引用符なしの値（数・真偽）      |
| `"` の中の `\n` `\t` `\r` `\\` `\"` | 複数行の文字列（`"""`）         |
| `#` から行末のコメント              | インラインのテーブル（`{ … }`） |

- 鍵と節の名前に使えるのは、英数字と `_` `-` `.` だけです。`.` は端に置けず、続けても書けません。
- `'...'` の中は `\` を解釈しません。
- 先頭の BOM（メモ帳が付ける目印）は読み飛ばします。

**読めない行があると、ビルドが止まります。** 行番号と理由が出ます。

| 書き方         | 理由                                                    |
|----------------|---------------------------------------------------------|
| `[a] b = "c"`  | 1 行に節と鍵が混ざっている                              |
| `"a.b" = "x"`  | 引用符でくくった鍵は読めない                            |
| `a = "x""y"`   | 引用符が途中で閉じている                                |
| `[a.]`         | `.` が端にある                                          |
| `a = "あ\qい"` | `\q` は使えない書き方                                   |
| `a = "abc\"`   | 文字列が閉じていない。`\` で終わる値は `"abc\\"` と書く |
| `a = 10`       | 値を引用符でくくっていない                              |

**同じ鍵を 2 回書いても、ビルドが止まります。** `ja.toml` と `ja/` の両方に書いたときも同じです。

```
`ja` に鍵 `messages.welcome` が2回書かれています: resources/lang/ja.toml と resources/lang/ja/messages.toml
```

## 知っておくこと

- 言語ファイルは TOML だけです。
- 入力の検査（`validate`）の文は、`[validation]` の節を書いても変わりません（[validation.md](validation.md)）。

まだ無い機能は [backlog.md](backlog.md) にあります。
